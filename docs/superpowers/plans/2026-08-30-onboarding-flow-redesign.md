# Onboarding Flow Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the onboarding "quiz" (product → quantity → goal → habit summary) to match `docs/UI_Design`'s reference screens pixel-for-pixel, add Hookah as a full product option, and fix the abrupt Register→Consent→form transition with real animation.

**Architecture:** One reusable `OnboardingScaffold` (header illustration + white rounded card: back link, progress bar, heading, content, button) composes four screens — `ProductSelectionScreen`, one config-driven `ProductQuantityScreen` (replaces four near-duplicate screens), `GoalSelectionScreen`, and a repurposed `OnboardingCompleteScreen`. `main.dart`'s existing `_OnboardingFlow` step-switch gets new `_Step` values and an `AnimatedSwitcher` wrapper instead of a full navigation rewrite.

**Tech Stack:** Flutter/Dart, `provider` for state, `flutter_test` for widget/unit tests, Python 3 + Pillow (already installed) for one-time asset cropping.

## Global Constraints

- Match `docs/UI_Design` reference screens exactly — no extra fields/UI beyond what's pictured (explicit stakeholder instruction).
- `costPerUnit`, `primaryMotivation`, `personalChallenges`, `pastQuitAttempts` are **not** collected in the new onboarding UI — `costPerUnit` becomes optional on `OnboardingController.recordProfile`, the other three stay optional/unused (no model changes needed for them).
- `baselineDailyUsage` must stay `> 0` (existing `OnboardingController` validation) — every quantity screen's interactive minimum is `1`, even though the reference slider's leftmost axis label reads "0".
- Both `QuitStrategy.gradual` and `QuitStrategy.dateBased` need a target date (`QuitDateCalculator` throws without one) — the inline calendar must appear for both, not just "Quit by a Specific Date" (existing behavior, preserved).
- Existing widget test keys `onboarding_complete_summary` and `onboarding_complete_continue_button` must keep working unchanged (referenced by `app_flow_test.dart`).
- Illustration assets are cropped once from `docs/UI_Design` PNGs and committed as static assets — rendered via `Image.asset`, no runtime image processing (same pattern as the existing `register_hero.png`).

```python
from PIL import Image

CROPS = {

        "docs/UI_Design/user on boarding 4.png", (68, 60, 698, 427)),

        "docs/UI_Design/after on boarding if ciagrettes selected this will open 4a.png",

}

OUT_DIR = "mobile/assets/images/onboarding"

if __name__ == "__main__":
    import os
    os.makedirs(OUT_DIR, exist_ok=True)
    for name, (src, box) in CROPS.items():
        im = Image.open(src).convert("RGB")
        crop = im.crop(box)

        crop.save(out_path)
        print(f"{name}: {crop.size} -> {out_path}")
```

```dart
  bool recordProfile({
    required ProductType productType,
    required double? baselineDailyUsage,
    double? costPerUnit,
    String? primaryMotivation,
    String? personalChallenges,
    String? pastQuitAttempts,
  }) {
    final validationError = _validateProfile(baselineDailyUsage, costPerUnit);
    if (validationError != null) {
      errorMessage = validationError;
      status = OnboardingStatus.error;
      notifyListeners();
      return false;
    }
    _workingUser = _requireWorkingUser().copyWith(
      productType: productType,
      baselineDailyUsage: baselineDailyUsage,
      costPerUnit: costPerUnit,
      primaryMotivation: primaryMotivation,
      personalChallenges: personalChallenges,
      pastQuitAttempts: pastQuitAttempts,
    );
    status = OnboardingStatus.idle;
    errorMessage = null;
    notifyListeners();
    return true;
  }

  String? _validateProfile(double? baselineDailyUsage, double? costPerUnit) {
    if (baselineDailyUsage == null || baselineDailyUsage <= 0) {
      return 'Daily consumption must be a number greater than 0.';
    }
    if (costPerUnit != null && costPerUnit < 0) {
      return 'Cost per unit must be a valid number and cannot be negative.';
    }
    return null;
  }
```

Note: `copyWith`'s `costPerUnit ?? this.costPerUnit` fallback in `nicotine_user.dart` is unaffected — `_workingUser` starts with `costPerUnit: null` from the constructor, and passing `null` through `copyWith` correctly leaves it `null` (the `??` only matters for a *second* `recordProfile` call, which isn't part of this flow).

```dart
              color: filled ? AppColors.sage : AppColors.sageLight,
```

```dart
// mobile/lib/screens/onboarding/widgets/onboarding_header_illustration.dart
import 'package:flutter/material.dart';

/// Fixed-aspect header illustration shared by every onboarding screen from
/// Product Selection through Goal Selection. Each PNG (see
/// mobile/tool/crop_onboarding_assets.py) already has its rounded corners
/// baked in against the app's cream background, so it renders as-is with no
/// extra clipping — same pattern as the existing RegisterHeroHeader.
class OnboardingHeaderIllustration extends StatelessWidget {
  final String asset;
  final double aspectRatio;

  const OnboardingHeaderIllustration({super.key, required this.asset, required this.aspectRatio});

  @override
  Widget build(BuildContext context) {
    final width = MediaQuery.sizeOf(context).width;
    final height = width / aspectRatio;
    return SizedBox(
      width: width,
      height: height,
      child: Image.asset(asset, fit: BoxFit.cover),
    );
  }
}
```

```dart
  @override
```
